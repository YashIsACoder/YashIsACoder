Skipping the work

When can Karp’s algorithm stop early, and still be exactly right? With Khoi Nguyen Nguyen, Trung Hieu Nguyen and Ting Bai.

The question

A system runs forever and every move pays a reward. Which moves give the best long-run average? When every move is deterministic, the answer is the best cycle you can reach, and Karp’s algorithm finds it exactly, one strongly connected component at a time.

Our idea

Many components can never beat what you already get by leaving them. Our cascade notices this while Karp’s table is still being filled, using rows it has already paid for, and stops. You only do the work for the parts that can matter.

What we found

The same answers as Karp on all 136 test graphs, and up to 411 times faster than Howard’s method on graphs built to trip it up. On real circuits Howard still wins, and we report that too.

  • 136graphs, every solver agreeing on every answer
  • 0wrong skips out of 3,037, each checked against full Karp
  • 96%of Karp’s work avoided when later components pay more

What we proved

Three results, each in a sentence and then exactly.

It’s safe

Every quick bound sits above the best cycle inside a component, so if any bound is no better than leaving, skipping can’t lose anything.

\lambda(K) \le \delta_{k+1}(K) \le \delta_k(K) \le M(K)
It’s exact

Skipping never changes an answer: the cascade returns the optimal gain for every state.

\mathrm{cascade}(v) = g^{*}(v) \quad \text{for every state } v
It’s never slower

A skipped component costs only the rows it took to rule out. In the worst case it is no slower than Karp.

O\Bigl(n + m + \sum_{\text{solved}} n_K m_K + \sum_{\text{skipped}} k_K m_K\Bigr)

\lambda(K) is the best cycle mean inside component K, M(K) its largest reward, and \delta_k(K) the largest one-row rise in Karp’s table after k rows.

Where it doesn’t help

On real ISCAS circuits Howard’s method wins 34 of 36. Ninety-five per cent of circuit components contain no cycle at all, so there is little left to skip, and most of the cascade’s time goes on comparing exact fractions.
