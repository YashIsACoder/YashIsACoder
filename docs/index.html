#research

An algorithms research project from COMP3821 (Extended Algorithm Design and Analysis), with Khoi Nguyen Nguyen, Trung Hieu Nguyen and Ting Bai.

deterministic MDPs · exact algorithms · C++

Skipping the work

When can Karp’s algorithm stop early, and still be exactly right?

The question

A system runs forever and every move pays a reward. Which moves give the best long-run average? When every move is deterministic, the answer is the best cycle you can reach, and Karp’s algorithm finds it exactly, one strongly connected component at a time.

Our idea

Many components can never beat what you already get by leaving them. Our cascade notices this while Karp’s table is still being filled, using rows it has already paid for, and stops. You only do the work for the parts that can matter.

What we found

The same answers as Karp on all 136 graphs, and up to 411× faster than Howard’s method on graphs built to trip it up. On real circuits Howard still wins, and we report that too.

● watch the solvers race the explainer ↗ all seven experiments ↗ source ↗
  • 136graphs, with every solver agreeing on every answer
  • 0 of 3,037skips were wrong, each one checked against full Karp
  • 411×faster than Howard on graphs built to be hard for it
  • 96%of Karp’s work avoided when later parts pay more

what we proved

It’s safe

Every quick bound sits above the best cycle inside a component, so if any bound is no better than leaving, skipping can’t lose anything.

λ(K)≤δk+1(K)≤δk(K)≤M(K)\lambda(K) \le \delta_{k+1}(K) \le \delta_k(K) \le M(K)λ(K)≤δk+1​(K)≤δk​(K)≤M(K)
It’s exact

Skipping never changes an answer: the cascade returns the optimal gain for every state.

cascade(v)=g∗(v)for every state v\mathrm{cascade}(v) = g^{*}(v) \quad \text{for every state } vcascade(v)=g∗(v)for every state v
It’s never slower

A skipped component costs only the rows it took to rule out. In the worst case it is no slower than Karp.

My part: I wrote the dmdp C++ library (strongly connected components, Karp’s table, exact fractions), designed the cascade and proved its skip condition, ran the experiments on the bounds, and built the visualisation site.
